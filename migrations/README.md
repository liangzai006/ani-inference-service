# Database migrations

`000001_inference_control_plane.sql` is the first migration for the independent Inference service; `000002_inference_lws.sql` extends it with distributed LeaderWorkerSet runtime shape; `000003_inference_bindings_publications.sql` separates runtime bindings, publication state, and observation history; `000004_operation_runtime_steps.sql` adds fenced runtime removal and absence-confirmation steps; `000005_delete_cr_step.sql` removes the CR projection only after runtime absence; `000006_update_previous_quota.sql` adds the explicit previous-generation quota release step for running updates; `000007_model_materialization_step.sql` adds the durable model materialization gate before runtime apply; `000008_model_readiness_fact.sql` persists known/unknown model readiness; `000009_inference_cr_binding.sql` adds the tenant-scoped CR control binding; `000010_applied_generation.sql` records service-level applied generation after a generation-fenced observation commit; `000011_invocation_verification.sql` adds the durable post-publication invocation verification step; `000012_inference_endpoint.sql` adds optional explicit runtime endpoint columns; `000013_inference_kserve_binding.sql` permits the KServe InferenceService runtime binding kind; `000014_inference_runtime_provider.sql` persists the per-generation deployment/KServe provider with deployment as the compatibility default; `000015_inference_kserve_llm_binding.sql` permits the KServe LLMInferenceService runtime binding kind; `000016_inference_gpu_plan.sql` stores the immutable accelerator request and plan; `000017_gpu_resolution_step.sql` adds the fenced optional GPU resolution step. Apply them in order before running the updated worker. The migration directory is the only DDL source for this repository; sqlc generation and integration fixtures must consume the complete ordered directory. `inference_runtime` remains the current aggregate projection, while `inference_services.applied_generation` explicitly records the latest generation observed after a generation-fenced observation commit; the dedicated tables hold binding and historical facts.

It deliberately does not copy `repo/deploy/migrations` from ANI. It has no shared Model/IAM/Quota/Core PlatformWorkload tables and no RLS/current-setting assumptions. Cross-domain IDs are validated through versioned service protocols. `inference_quota_reservations` stores an external reservation reference; it is not a quota ledger.

Migration credentials and runtime credentials are separate. Every generated query must include the applicable `tenant_id` predicate; absent tenant scope is an error. The migration has been replayed in the user-provided local `recycling-postgres` container into the isolated `ani_inference` database; controller/Kubernetes and cross-service quota protocol verification remain pending.
