# Inference 分阶段交付计划

状态：设计草案，非自动执行授权。目标行为以[规格](../specs/inference-service.md)为准；当前事实以[状态](../execution/status.md)为准。

## INF-00：固定来源与批准边界

输入：用户重构准则、固定 layout/Network/旧 ANI 快照。本轮产出设计包、迁移能力清单和独立评审；不创建新服务代码、不修改旧 API、无集群操作。确认 PostgreSQL 权威 + InferenceService CRD 投影、资源字段和首个验证配置后，再冻结实施包。

每个后续包记录源 commit/tree、依赖版本、允许路径、验收范围和实际工作树；不把 `main/latest` 当可复现输入。现有工作区和前端未提交文件保留。

## INF-01：独立骨架、gRPC 与持久受理

在独立目标位置，从固定的干净 layout 分支运行其生成器；记录模板 commit、命令、工具版本、生成后 tree 和差异。拟定模块名为 `github.com/zhangzhe-ctrl/ani-inference-service`，只是提案，不代表已创建远程仓库。

允许：新服务 `cmd/internal/api/migrations/configs` 和必要脚本/文档；不允许导入 ANI runtime、复制旧 Proto、修改其他领域 DB、应用集群资源。固定新 Proto、PG/sqlc 和迁移/运行双凭据，完成 V-01、V-02、V-07 的适用范围。无真实引擎启动证据时只称“受理/进程切片”。

## INF-02：隔离的完整 runtime 切片

依赖 INF-01，固定一个模型、一个引擎配置、单副本、实际 Kubernetes 版本及 client-go/controller-runtime 版本组。无卡正常启动与传卡渲染分别验收，不命名为 CPU 专用切片。

实现单一 Controller 执行入口、持久工作重建、原生资源 watch、制品装载、加载探测、发布/撤销、操作后持续观察、停止/重启/删除及故障恢复。先单测/真实 PG/envtest，再在单独授权的隔离 K8s 和真实引擎/数据面验证 V-03–06、V-09–10。

fixture 替代某依赖时明确层次。未接 IAM 或真实 publication，只能记录受控切片，不宣称普通用户创建后即可调用。涉及共享 CRD/Gateway/storage class/GPU 设备插件时先核对集群级影响；namespace 不同不自动代表隔离。

## INF-03：依赖与功能完整性

固定 IAM Workload、Model、数据面和必要资源领域契约，完成 V-08、V-11、V-12。明确 quota、storage/network 关联的请求身份、幂等结果查询、重试、补偿及本地提交责任，先保留旧共同事务权威，不复制临时账本。

逐项补齐 Embedding、访问/限流策略、日志流、GPU 调度和单节点边界；LWS/多节点、扩缩容/多副本、自定义高级引擎参数分别记录支持矩阵和验收，不能默默删掉旧能力。单活之外的多副本执行与自动故障转移单列 fencing 证据。

## INF-04：消费者接线和存量交接（独立授权）

前置条件是适用产品链验收通过，不是“服务能启动”。本包才允许另行批准的 Gateway/SDK/路由变更；无前端实现。

切换清单必须包含：明确租户/资源集合、旧写入者停止与不可继续写的证据、在途 operation 处理、模型/网络/存储引用保护、迁移数据校验、路由切换、失败回滚和清理范围。先停旧写入并排除旧在途执行，再迁移/绑定目标资源，启动新写入者；回滚同样排除新写入者，不能新旧并行试跑同一资源。

只迁移已验收能力资源；未迁移继续由旧服务完整负责。清理旧路径必须有调用方和资源归属证据。没有本包授权，不更改已有测试环境部署、数据或路由。

## 各包退出要求

沿用生成器提供的可执行门禁，增加对应领域测试、真实依赖/正式进程/产品链记录；不套用旧 ANI 架构豁免门禁。结果标 `pass/fail/not_verified`。源码通过、容器构建、集群部署、公开接入、存量切换分别给证据，不相互代替。
