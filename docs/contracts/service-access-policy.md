# 推理 AK 访问策略

推理访问策略是 Inference 持有的租户级独立资源，不绑定推理服务。一个 AK
必须绑定一个同租户策略，一个策略可绑定多把 AK。策略包含允许调用的
`served_model_name` 列表和 QPS、RPM、RPH；模型列表为空时拒绝所有模型，
各限额为 0 时对应时间窗口不限。AK 的到期和撤销仍是凭证生命周期属性。

## 管理

受信 Governance mTLS 身份可以调用 `InferenceAccessKeyService` 的策略创建、
查询、列表、完整更新、删除和 AK 策略绑定 RPC。策略更新立即影响其绑定的
AK；已被 AK 绑定的策略不能删除。创建 AK 必须提供 `policy_id`，不再接受
AK 上的模型、服务范围或限流配置；绑定策略时要求 AK 与策略同属调用租户。
管理操作及策略更新写入审计记录。旧服务策略管理 RPC 已从授权列表移除。

Governance BFF 的对应接口为 `/api/v1/inference-policies` 和
`/api/v1/inference-keys/{key_id}:bind-policy`；具体请求与权限以 Governance
的 `docs/contracts/inference-keys.md` 为准。管理页面和目标环境部署需要单独
完成。Higress 只承载 OpenAI 兼容的 `/v1/...` 推理调用。

## 请求执行

Higress 从请求体解析 `model`，鉴权适配器通过 mTLS 调用
`CheckInferenceAccess`。Inference 校验 AK 后根据发布事实解析唯一有效服务，
同时拒绝仍有路由可能的同名服务歧义，且不信任调用方提交的服务或租户头。
策略模型名称必须精确匹配。当前仅允许 AK 所属租户调用同租户发布的模型；
取消服务策略绑定不自动授予跨租户调用。

策略的限额以 `(租户, AK, UTC 时间窗口)` 计数，绑定相同策略的 AK 各自独立。
各窗口在同一事务中扣减，任一窗口拒绝时不消耗其他窗口。更新策略不清空已有
窗口计数。鉴权与策略修改、AK 重新绑定及撤销通过数据库行锁和版本检查同步。

缺失或无效 AK 返回 401，模型或策略拒绝返回 403，超过额度返回 429，
依赖不可用时拒绝放行。

## 迁移

应用 `000026_inference_access_policies.sql` 后，旧 AK 的 `policy_id` 为空，
无法调用；按新规则创建策略并重新绑定或重新签发 AK。旧服务策略与旧 AK
范围和限额字段不参与鉴权，历史数据保留但不会自动迁移。新应用和管理端须
先接入新合同后再切换，升级需要安排调用中断窗口。

两个后端均固定引用包含本合同的远程 API 模块版本
`v0.1.2-image-registry.2.0.20261029033104-a8b505b9e2ea`，该版本对应已推送的
提交 `a8b505b9e2eaf01a4f33c9d7c0d37436724374ba`，无需本地 `replace`。
该提交已合并到主线，尚未创建正式版本标签；部署时需要确保模块版本持续可获取。
